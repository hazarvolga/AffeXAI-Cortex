# AffeXAI UX Principles

> This document defines the foundational UX philosophy for AffeXAI. All UI/UX decisions must align with these principles.

---

## Core Identity

AffeXAI's UI must feel like an **intelligent brand advisor** — not a dashboard, not an analytics tool.

---

## The Four Pillars

| Pillar | Description |
|--------|-------------|
| **Calm** | Quiet confidence. No visual noise. Breathing room. The interface should feel like a trusted consultant, not a control room. |
| **Premium** | Every pixel matters. Typography, spacing, color — all must convey sophistication and expertise. |
| **Minimal** | Show only what matters. Hide complexity. Reveal depth progressively. |
| **Action-Oriented** | Every screen should answer: *"What should I do next?"* Guidance over observation. |

---

## What We Avoid

> [!CAUTION]
> The following patterns are **explicitly prohibited** in AffeXAI:

- ❌ **Analytics-heavy dashboards** — We are not a BI tool
- ❌ **Charts without guidance** — Data without insight is noise
- ❌ **Overwhelming interfaces** — Cognitive load destroys trust
- ❌ **Feature overload** — More features ≠ more value
- ❌ **Generic SaaS patterns** — We are a brand intelligence advisor, not a generic tool

---

## The Guiding Question

Before any UI decision, ask:

> **"Does this guide the user toward their next best brand decision?"**

If the answer is no, reconsider.

---

## Implementation Guidelines

### Visual Design
- Use generous whitespace
- Limit color palette to reinforce brand trust
- Typography should be clear, confident, readable
- Subtle animations only — no distracting motion

### Information Architecture
- Progressive disclosure over upfront complexity
- Lead with recommendations, support with data
- Every metric shown must have a purpose
- Default to simplicity, reveal depth on demand

### Interaction Design
- Primary actions should be obvious
- Reduce decision fatigue with smart defaults
- Provide clear next steps on every screen
- Error states should guide, not blame
